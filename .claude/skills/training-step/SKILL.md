# Skill: writing a training module step

This skill applies whenever a task asks to add, write, reorder, split, remove or revise a step of
a training module (`src/app/[locale]/training/aN/`), or the exercise project a step opens. For
illustrations (SVG figures), use the `training-figure` skill: this skill only says where a figure
is referenced.

## How a step works

- A module is `src/app/[locale]/training/aN/`: `step-ids.ts` (stable ids), `steps.ts`
  (`buildAnSteps(t)` returns the ordered `StepData[]`), `page.tsx` and `[step]/page.tsx` (both
  generated by `createTrainingModulePages("aN")` in `training-pages.tsx`). Modules are registered
  in `training-module-ids.ts` and `training-modules.ts`.
- `StepData` (`ModuleStepper.tsx`): `id`, `kind` (`"theory" | "exercise" | "synthesis"`),
  `title`, `body` (array of Markdown blocks joined by a blank line), optional `cta`
  (`templateId`, `exerciseLabel`, `solutionLabel?`, `primaryMode?: "solution"` for an
  observation step on a solved project, `autostartSimulation?`).
- Text lives in `src/i18n/messages/{fr,en}/training.json` (namespace `training`): `<key>Title`
  (string) and `<key>Body` (string array, read with `t.raw`). a0 and a1 keys are unprefixed
  (`theoryTimerBody`), a2 to a4 keys carry the module prefix (`a2TheoryEdgesBody`): follow the
  module's existing pattern. Shared labels already exist: `ctaExercise`, `ctaSolution`,
  `openExerciseCta`.
- Routing: the first step is served at the module URL (`/formations/aN`, `/en/training/aN`), every
  other step at `/training/aN/[step]` with the step `id` as slug, identical in both locales (only
  the `/formations` / `/training` prefix is translated, in `routing.pathnames`,
  `src/i18n/routing.ts`). `generateStaticParams` and the sitemap derive from `steps.ts`: adding a
  step never touches `routing.ts` or `sitemap.ts`.
- Metadata (`generateStepMetadata` in `training-pages.tsx`): a **theory** step after the first
  is indexed and needs `public.metadata.trainingSteps.<aN>.<step-id>.{title,description}` in
  `src/i18n/messages/{fr,en}/public.json` (absolute title, no site suffix appended). Exercise
  and synthesis steps get a derived title, the module description and `noindex`, and must
  **not** have a `trainingSteps` entry. The first step uses the module's metadata
  (`trainingAnTitle` / `trainingAnDescription`). The sitemap lists module pages and theory steps
  after the first only.
- Rendering: the page `h1` is the module title (`PageTitle`), the step title is an `h2`, the body
  goes through `MarkdownBody` (`src/ui/lib/markdown-body.tsx` with `renderMarkdown`,
  `src/ui/lib/markdown.ts`: GFM, line breaks, sanitized HTML; tables, `<details>`/`<summary>`,
  `<figure>`/`<img>` are kept).
- Progress: the step `id` is the saved-progress key (`TrainingProgressRepository`) and
  `Object.values(AN_STEP_IDS)` gives the step order for the module's progress counter on
  `/training` (`training/page.tsx`, `TrainingModuleRow.tsx`).
- Exercise projects: `cta.templateId` is an id of `PROJECT_TEMPLATES` (`src/templates/index.ts`),
  opened via `/app?template=<id>` (plus `&template-mode=solution` for the solution button).

## Before starting: mandatory questions

Don't write before getting clear answers. If the request doesn't settle them, ask:

1. **Module and position**: which module, between which existing steps? Is it a new step, a
   revision, a split, a reorder or a removal?
2. **Learning objective**: what will the reader be able to do after this step, in one sentence?
   Which notions are new, which are assumed (and from which earlier step or module)?
3. **Kind**: theory, exercise, or synthesis? A theory step with an observation project
   (`primaryMode: "solution"`, `autostartSimulation`)?
4. **Exercise project**: reuse an existing template (which id?) or create one? With a solution?
   What does the exercise version contain (empty, partial, a naive version to fix)?
5. **Example**: does it use the common thread (the parking barrier from a0) or a new system?
6. **Figures**: does the step need an illustration (then the `training-figure` skill)?

When the pedagogical intent is ambiguous (what to teach, what the reader already knows, how much
to give away in hints), ask rather than guess. Never rename or remove an existing step id
without the developer's explicit approval: the URL is indexed (no redirect exists) and saved
progress pointing to it is lost.

## Mechanics checklist

Apply in this order.

### 1. Step id: `aN/step-ids.ts`

- [ ] Add the key in the `AN_STEP_IDS` object **at the same position as in `steps.ts`** (the
      object order is the progress order on `/training`).
- [ ] kebab-case slug, prefixed by its kind like its neighbours (`theory-…`, `exercise-…`,
      `synthesis-…`), unique in the module, readable in both locales (it is the URL in FR and EN).

### 2. Step entry: `aN/steps.ts`

- [ ] Insert the `StepData` at its position: `id`, `kind`, `title: t("…Title")`,
      `body: t.raw("…Body") as string[]`, and `cta` for an exercise/synthesis.
- [ ] The first step of a module must stay a theory step (tested).

### 3. Text: `src/i18n/messages/{fr,en}/training.json`

- [ ] Add `…Title` and `…Body` in **both** files, same keys, same position in the file, same
      number of body blocks in the same order (a figure in block 2 in FR is in block 2 in EN).
- [ ] New CTA label only if `ctaExercise` / `openExerciseCta` / `ctaSolution` don't fit.
- [ ] If the step changes the module's scope, update `aNIntro` and the module metadata
      (`trainingAnDescription`) accordingly.

### 4. Metadata: `src/i18n/messages/{fr,en}/public.json`

- [ ] Theory step after the first: add `metadata.trainingSteps.<aN>.<step-id>` with `title` and
      `description` in both locales. Title: specific, at most 60 characters **including** its own
      suffix (follow the existing ones: `… : formation` / `…: training`). Description: specific,
      around 150 to 160 characters at most.
- [ ] Exercise or synthesis step: no `trainingSteps` entry. A step whose kind changes
      (theory ↔ exercise) adds or removes its entry.
- [ ] Removed or renamed step: remove or rename its entry.

### 5. Exercise project (when a template is created or changed)

- [ ] Template file in `src/templates/training/{grafcet,ladder}/<name>.template.ts`, exporting
      `create<Name>Project()` and, if there is a solution, `create<Name>Solution()`. Reuse the
      helpers in `src/templates/training/utils/` (`training-variables.ts` for inputs with their
      physical behaviour, `ladder-dsl.ts` for sections, `grafcet-ladder.ts`).
- [ ] Register it in `PROJECT_TEMPLATES` (`src/templates/index.ts`) with `hiddenFromCatalog: true`
      and a `statement` (Markdown shown in the app) consistent with the step body: same values,
      same variable names, same numbered work.
- [ ] Add `label` and `description` for the id in `src/i18n/messages/{fr,en}/templates.json`
      (`TemplateId` is derived from the FR keys).
- [ ] Co-located test `<name>.template.test.ts`: simulate the scenario of the statement with
      `PlcScenario` (`@tests/utils/plc-scenario`): the exercise version shows the expected starting
      behaviour, the solution meets every self-check criterion of the step.
- [ ] Templates bypass migrations: the project must be built at the current
      `PROJECT_SCHEMA_VERSION` (`src/templates/index.test.ts` checks it, plus JSON round-trip and
      an error-free analysis/compilation for both variants).
- [ ] `cta.templateId` is a plain `string` in `StepData`: check that the id exists in
      `PROJECT_TEMPLATES`.
- [ ] If a revision changes values or variable names, update the step body, the `statement`
      and the template test together.

### 6. Links and figures

- [ ] No hard-coded internal URL in a body: Markdown links are not localized. Refer to the user
      manual as the existing text does ("le manuel utilisateur (menu Aide)"); a real link goes
      through `PublicLink` in a component (see `a0/renderManualLink.tsx`), and needs the
      developer's agreement.
- [ ] Figures: `public/training/…`, referenced in a body block as
      `<div style="text-align:center"><figure><img src="/training/…svg" width="…" alt="…" /></figure></div>`.
      A figure with text has an `-en.svg` variant used by the EN body. The `alt` describes what
      the figure teaches, in the locale of the body. Creating or editing the SVG: `training-figure`
      skill.

## Pedagogical writing standard

Target reader: someone with no prior course in automation, electricity or Boolean logic. Apply
this checklist to every step written or revised.

### Notions and vocabulary

- [ ] One main idea per step. Split a step that introduces more than a handful of new notions.
- [ ] Every technical term is defined at its first occurrence in the module, in plain words, with
      an everyday example when possible (automate/PLC, réseau, mnémonique, rémanent, télérupteur,
      front, hystérésis, ENO, POU, contacteur, réceptivité...). Bold the term where it is defined.
- [ ] Prerequisites are recalled in one or two sentences where they are used, never as a bare
      "voir A1". A short recall beats a cross-reference the reader can't follow.
- [ ] Standards and alternative notations (IEC 60848, IEC 61131-3, NF C 03-190, GEMMA, rule
      numbers...) go in a final `<details><summary>Pour aller plus loin</summary>…</details>`
      (EN: `Going further`), not in the main text.

### Structure

- [ ] No dense paragraph: turn procedures into numbered steps, enumerations into lists,
      comparisons and truth tables into GFM tables.
- [ ] A figure where the text describes something visual (a diagram, a timing diagram, a
      network), placed right after the block it illustrates.
- [ ] Headings inside a body start at `###` (the page `h1` is the module title, the step title is
      the `h2`); never skip a level.
- [ ] Reuse the common thread: the parking barrier from a0 (`voiture_detectee`,
      `lever_barriere`, `barriere_levee`, `places`) or a system already met in the module, before
      introducing a new one.
- [ ] Practice comes early: avoid more than two or three theory steps in a row without an
      exercise or an observation step (`primaryMode: "solution"`).

### Exercise and synthesis steps

- [ ] The complete statement is in the page, not only in the app: context, inputs and outputs
      with their names and physical nature (push button, switch, limit switch, wired normally
      closed...), and the numbered work to do.
- [ ] Concrete values everywhere: durations, thresholds, presets, ranges, counts.
- [ ] Optionally an expected behaviour figure (timing diagram) that does not give away the
      solution.
- [ ] Self-check criteria: a "how to tell it is right" block listing observable results in
      simulation (which output, after which input, for how long) and "the analysis panel reports
      no error" when relevant.
- [ ] Progressive hints in `<details><summary>Indices</summary><ol>…</ol></details>` (EN:
      `Hints`), from a guiding question to a near-answer; never the solution itself.
- [ ] Reading exercises ask for a prediction before simulation, and answers go in
      `<details><summary>Voir les réponses</summary>…</details>` (EN: `Show the answers`).
- [ ] The exercise project does not give the answer away (section titles, comments, variable
      names).

### Theory steps

- [ ] Start from a concrete situation, then the rule, then an example in Studomate syntax.
- [ ] A check question when useful: `<details><summary>Question de vérification</summary>…</details>`
      (EN: `Check question`).
- [ ] State only what Studomate actually does: verify any claim about the editor, the analyser or
      the simulator in the code before writing it.

## FR/EN rules

- [ ] Same content in both locales: same blocks, same figures (with `-en` variants), same values,
      same hints. Translate naturally, not word for word; keep variable names, code and
      expressions as they are in the project (they are not translated).
- [ ] Use the expression dialect of each locale in prose about operators (`ET`/`OU`/`NON` in FR,
      `AND`/`OR`/`NOT` in EN), as the existing text does.
- [ ] Punctuation: a colon, not an em dash, to introduce an explanation, a subtitle or a list
      ("Exercice : séquence linéaire"); for an aside, parentheses, commas or a new sentence. French
      typography: a space before `:`, `;`, `?`, `!`. The only em dash allowed is the site-name
      suffix of page titles, added by the metadata template.
- [ ] Vouvoiement in FR, consistent with the rest of the module.
- [ ] Text meant to be indexed stays in the step `title`/`body` and metadata messages; never put it
      only in a client-only, lazy or WebGL component.

## Verification

Mid-task, run only the affected tests:

```bash
npx jest "src/app/\[locale\]/training" src/app/sitemap.test.ts src/i18n/messages
npx jest src/templates/index.test.ts src/templates/training/<path>/<name>.template.test.ts
```

- `training-modules.test.ts`: unique ids, first step is theory, same ids and kinds in FR and EN,
  `trainingSteps` entries exactly for theory steps after the first.
- `training-pages.test.tsx`, `training-paths.test.ts`, `ModuleStepper.test.tsx`: routing,
  metadata, rendering. Some assert specific step ids (`theory-timer`, `exercise-linear`,
  `synthesis-parking`, `theory-edges`...), as does `sitemap.test.ts`: update them only if that
  step was deliberately renamed.
- `src/i18n/messages/messages.test.ts`: identical key sets in FR and EN.
- `src/i18n/messages/metadata-titles.test.ts`: title lengths.
- `src/app/sitemap.test.ts`: theory steps listed, exercises and first steps excluded.

At the end of the task, run `npx tsc --noEmit` and `npm run lint` (CLAUDE.md cadence). Don't run
`npm run build`. Don't commit.

## End-of-task report

Besides the usual summary, the report states what was checked for SEO (CLAUDE.md, public pages):

- metadata: indexed or `noindex` per kind, `trainingSteps` title and description present in both
  locales, lengths;
- indexing: sitemap derived from `steps.ts`, no removed or renamed id leaving a dead link (grep the
  id across `src/` and the message files);
- locale parity: same blocks, figures with `-en` variants, same keys;
- structure: one `h1`, body headings from `###`, `alt` on every informative figure;
- rendered content: no indexable text moved into a client-only component;
- any id renamed or removed, with its impact on saved progress and indexed URLs.
